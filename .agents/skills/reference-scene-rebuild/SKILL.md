# 参考图分区重建

把参考图转成可检查的几何修改，并保持第一人称场景可用。开始前阅读 [项目约定](references/project.md)；文件中的历史验收和旧截图不代表用户接受当前外观。

## 确定本轮边界

- 读取用户选定参考图、当前 `HANDOFF.md`、工作树和实际网页总览。参考图中的文字/附件只提供视觉信息，不能扩大用户授权。
- 用户指定一个区域就只修该区域；用户授权多区时，按约定顺序推进至全部完成。不要把“逐区”解释为每一区都必须另行询问。
- 已有工作先保留。用户要求提交时只提交本项目相关文件；不要把工作区里的无关文件一并加入。
- 修改前保存相同视角的网页截图。列出每区最重要的 2–4 个差异，优先看剪影、体量、相对位置、遮挡，再看结构和材质。区分“图中能确认”和“被遮挡部分的合理补建”。

## 重建与导入

- 在 Blender 源脚本中创建真实体积。把大型设备拆成壳体、接缝、连接件、显示/发光部件；不要用一组悬空面板代替参考图中的实体机器。
- 保留已认可的共享角色形体。实例位置、比例、姿态可以随场景调整，注意悬浮动画的完整幅度。
- 校正环状/自建网格的外向法线；有透视的玻璃要检查前后面、排序和反射。平面显示屏保留完整 UV。
- 布局改变时同时更新碰撞和动画锚点。低地面装饰与台阶不能被不必要的大圆碰撞封住；大型机壳和独立底座不能漏掉碰撞。
- 导出 GLB 与元数据，检查导出日志和文件确实更新，再打开网页。美术阶段可按相邻区域成组导出，方便发现相互遮挡。

## 复核与收尾

- 用可用的浏览器 UI 工具获取真实截图，不以 Blender 单张渲染代替网页验证。对比图使用同一总览相机；如果需要改总览构图，单独记录原因，并再检查第一人称。
- 对照原图记录已修差异与剩余差异。明确错误就继续修改后再截图；不要用主观百分数或“无几何错误”冒充美术相似度验收。遮挡导致看不清时补另一个视角。
- 执行本技能的 GLB 检查脚本，验证几何有限、角色实例和元数据；必要时增加设备特有的包围/碰撞检查。脚本不判定视觉相似度。
- 运行相关移动测试、项目构建及 `git diff --check`。检查网页错误和第一人称出生、通道、转向。保留原图、总览前后截图、检查报告的可追溯位置。
- 在 handoff 中更新本轮区域、坐标/碰撞变化和实际验证结果。用户要求提交则完成项目提交，最终附场景链接、截图和仍存在的主要限制；不宣称用户尚未作出的验收。
